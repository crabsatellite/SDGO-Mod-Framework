# 每日双倍时间（Beta）

[English](daily-rewards.md) · [返回功能目录](../README.zh-CN.md)

`daily_rewards` 是对战服务器 Mod。启用后，每天按 **BattleServer 所在机器的本地时间**，
在 **18:00（含）至 22:00（不含）**将正常战斗结算的 **G 币、驾驶员经验/军衔星数、机体经验**翻倍。
玩家不需要安装客户端 Mod，也不需要修改客户端时间或使用特殊启动器。

按生成该玩家最终结算的时刻判断，开局时间不决定加成。原生活动、道具等加成先按游戏自身规则计算，
本 Mod 对原先的最终收益应用一次 ×2；对应差额并入原生的活动奖励明细，随后由游戏继续处理机体经验、
数据库请求和客户端结算包。修理费、能量消耗、胜负、评级、竞技分与随机掉落不翻倍。
额外的任务/成就奖励、充值、商城、赠送与 GM 发币不属于正常战斗结算。

若另外启用 [战斗贡献奖励（Beta）](battle-rewards.zh-CN.md)，该组件在本 Mod 之后按贡献规则重算 G 币，
并将本 Mod 的相同时段系数用于 G 币和 MB，避免重复翻倍；驾驶员与机体经验仍由本 Mod 处理。
贡献奖励以整场共享的结算快照冻结时段系数，跨边界时以该组件的规则为准。
仅安装 `daily_rewards` 不会新增 MB 发放，也不需要部署贡献奖励工作器。

## 安装和配置

需要随本 Mod 更新的 **1.1.4 或更新框架**，以及支持的
`BattleServer-548A891D-0046C000`。服主自行退出准备更新的对战服务器，再使用该版本发行包安装。

更新前备份现有框架、符号表和配置。安装器会保留其他 Mod 目录，但会更新包内同名文件。
如果现有符号表包含自定义 Mod 的额外条目，安装后、启动前将这些条目合并回对应主机符号表，
保留本版本新增的 `battle.reward.final.*` 和 `battle.reward.layout.*` 各十项；
遇到同名但内容不同的条目应先核对实际 EXE。其他 Mod 的 DLL、数据和设置应保留。

安装命令（在发行包目录运行）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install_server.ps1 -ServerRoot "D:\SDGO\Server" -Role Battle
```

在 SDGO Mod Manager 的“每日双倍奖励”中为每个对战服务器设置“双倍开始时间”和“双倍结束时间”，
诊断日志点“显示开发信息”后显示。配置保存在 `sdgo/mods/daily_rewards/config.ini`：

```ini
[settings]
StartTime=18:00
EndTime=22:00
Trace=0
```

没有 `config.ini` 时使用清单中的同样默认值。本 Mod 默认启用。修改设置后重启相应 BattleServer；
每日开始/结束按结算时钟自动判断，无需定时重启。

时间严格使用 `HH:MM`，支持分钟和跨午夜，例如 `23:30` 至 `01:15`。
开始和结束相同，或小时/分钟无效时拒绝加载，不自动解释为全天。
采用服务器系统时区；分布在多台机器时，服主应统一各机器的时区和时钟。

`Trace=1` 在日志中记录最初 32 次生效结算的三项前后值，不记录玩家账号或密码。
启动日志应出现 `loaded Daily double battle rewards (Beta)`，以及配置的本地时间段。

## 关闭和卸下

关闭服务器后，在 Manager 中关闭本功能，再启动服务器。
只卸除此功能时，关闭服务器后移走 `sdgo/mods/daily_rewards/`，保留公共框架和其他 Mod。
通用安装器的 `-Uninstall` 卸载整套框架，不是单独卸除此功能。

## 覆盖范围

覆盖当前服务器结算分发器的全部十条原生路径：个人房、普通团队、Tag、死亡/Grid、队长、原生 AI/战舰、
模式 13/14 和任务模式 5/8/10。原生不发奖的情况仍不发奖。单次结算字段为 16 位，翻倍超过 `65535` 时饱和到该上限，防止回绕。

## 检查是否生效

1. 查看 `sdgo/logs/sdgo.log`，确认此 Mod 已加载，并核对日志中的时间段及服务器时区。
2. 默认时段外想立即测试时，临时设置一个包含当前服务器时间的时段并重启参与测试的 BattleServer；不要修改系统时钟。
3. 打开诊断日志（`Trace=1`）后，最初 32 次生效结算会记录同一次结算的三项前后值，例如
   `pilot EXP 100->200, G 200->400, unit EXP 300->600`。对照同一次结算的活动奖励明细，不要用两场的总数相除判断。
4. 测试后恢复原时段，按需关闭诊断日志并重启。

实现细节与开发测试见[英文说明](daily-rewards.md)。
