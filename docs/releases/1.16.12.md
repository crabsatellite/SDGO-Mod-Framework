## 中文

机体导入：商城详情和扭蛋结果里的「性能」「使用」栏改由作者填写。

- 「机体导入」面板新增「性能说明」和「使用说明」两栏，每栏最多 99 个字符。确认导入后，文字写入这台机体新的物品类别，在商城详情和扭蛋结果框的「性能」「使用」栏显示。
- 之前新物品类别整条复制所选模板物品，这两栏留着模板那台机体的文字，常常是另一台机体的英文或泰文说明。现在模板的这两段文字不再沿用；没有填写时栏位为空，面板会给出提示，不会阻止确认。
- 机体定义 JSON 和制作项目新增可选字段 `item_text`（`description`、`usage`）。只有填写了文字的项目才会导出这个字段，未填写的项目仍可被旧版 Manager 读取。
- 这两段文字只写入玩家客户端包，不写服务端。已导入的机体在面板里补填文字并重新确认，生成新的玩家客户端包后生效。
- 机体导入指南和原生机体包接口文档补充了这两个字段的位置和长度。

## English

Unit import: the 「性能」 (description) and 「使用」 (usage) fields in shop details and capsule results now come from the author.

- The **机体导入** (unit import) panel adds **性能说明** and **使用说明**, up to 99 characters each. On confirmation they are written into the unit's new item category and appear in the 「性能」 and 「使用」 fields of shop details and the capsule result dialog.
- The new item category used to copy the chosen template item whole, so these fields kept the template unit's text, often another unit's English or Thai description. The template's text is no longer kept; an empty field stays empty, and the panel shows a notice without blocking confirmation.
- Unit definition JSON and authoring projects accept an optional `item_text` (`description`, `usage`). Projects export it only when text is filled in, so projects without it stay readable by earlier Managers.
- The text goes only into the player client package, not the server. For a unit already imported, fill it in and confirm again; it takes effect with the new player client package.
- The unit import guide and the native unit archive interface describe both fields' offsets and capacity.
