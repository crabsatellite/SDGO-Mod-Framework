## 中文

机体导入现在支持配套的原生技能效果参数记录，并在应用前拒绝缺失或冲突的参数依赖。

- 新增 kind 79／89 字节目标记录 profile、制作资料摘要与数量显示；完整批量发布物可携带它，或复用经过校验的配套客户端原版。
- 服务端预检及应用在数据库变更前验证 skill `+284` 参数引用；拒绝缺项、身份／类型冲突、与原版同编号不同内容及非有限参数值。
- 原生目录在分配和登记前检查同一依赖，避免缺失参数进入后续技能消费者。原生开发测试可核对该类型的登记与正常退出释放。
- 补充通用的变形前后三槽参数说明、独立编号与兼容复用规则，以及条件型技能实际触发和完整对局验证方法。
- 开发测试 SDK 将四向输入限定在已启用的任务导航中，保留普通 PvP 的输入所有权，并在新对局重置任务路线状态。
- 机体编辑器新增有向多形态 profile，保留 2–64 条完整记录的循环和辅助入口；确认／导出同时生成同版服务端形态图请求，使用现有停服应用与独立所有权核验。
- 客户端按形态缓存多个新增模型，循环回到原始形态时复用卡组模型；按原生控制器和双模型的销毁顺序处理其余所有权。
- 补齐机体可选替代模型路径（`+738`）的类型与核心依赖校验；拒绝把不兼容布局的数值当作模型文件名，错误在原生登记前可见。
- 复用缓存模型时的空变形动画恢复限于目录确认的存活、已提交导入形态链；继续使用原生等待与退出，不绕过服务端许可。
- 默认预设安装与既有分卷资源归档共存，检查分卷大小、索引和资源重名，并保留服主主目录。
- 增加非默认的四形态循环通用配方，并明确旧版三阶段与新版一般有向图的版本范围；最小机体示例使用目标服务端允许的编号域。

机体、技能、参数记录、图片及来源转换工具由内容作者分别提供，不随通用框架和 Mod 程序发布。记录通过不能替代实际效果与战斗验收。

## English

Unit import now supports paired native skill-effect parameter records and rejects missing or conflicting parameter dependencies before application.

- Add the kind-79 / 89-byte target profile, authoring summaries and a separate count. Complete batch publications can carry it or reuse a verified compatible original from the paired client.
- Server preflight and application validate skill `+284` parameter references before database changes. Reject missing records, identity/type conflicts, changed originals at an occupied ID and non-finite parameter values.
- Native catalog validation checks the same dependency before allocation and registration, keeping missing parameters out of downstream skill consumers. Native developer tests can verify registration and normal-shutdown destruction for this record type.
- Document normal/transformed parameter triplets, independent identities and compatible-original reuse, plus condition-aware activation and complete-match acceptance using generic examples.
- Keep four-direction developer inputs scoped to enabled mission navigation, preserve ordinary PvP input ownership, and reset mission route state for each new battle.
- Add a directed multi-form editor profile for 2–64 complete records, retaining cycles and auxiliary entries. Confirmation/export produces matching server graph requests through the existing stopped-server and independent-ownership checks.
- Cache multiple additional models by form ID, reuse original deck models when a cycle returns, and reconcile remaining owners with native controller/live-pair destruction order.
- Validate the optional unit model override (`+738`) and its critical resource dependency, rejecting incompatible numeric bytes used as a model filename before native registration.
- Recover empty transition animations on reused imported models only after the catalog verifies a living, owned and already committed chain, using the native WAIT/exit path without overriding server authority.
- Install default presets alongside split owner resource archives, checking part extents, the index and resource collisions while preserving the primary content.
- Add a non-default generic four-form cyclic recipe, distinguish published linear three-stage support from the new general graph profile, and keep minimal unit examples inside the server's native ID domain.

Content authors supply units, skills, parameter records, artwork and source-conversion tools separately. Generic framework/Mod programmes contain none of those owner inputs. Record validation does not replace effect or battle acceptance.
