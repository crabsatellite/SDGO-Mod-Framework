## 中文

修复启动前更新交接中可能丢失启动请求或无法启动后台的问题。

- 后台检查期间的新启动请求会独立入队，完成及取消的请求及时退役。
- 管理会话重启或切换后，进度窗口会重新连接并提交同一启动请求；完成状态会在启动前再次核对，避免重复执行。
- 停止中的消费线程会交接新请求；游戏启动优先于常规定期同步，后台异常会返回具体原因。
- 支持客户端 Manager 工作区通过 Windows 目录联接重定向到其他目录。
- 后台初始化失败会回传具体错误并释放工作区锁；更新后仍在运行的旧后台及旧进度窗口会明确提示退出。

## English

Fixes lost launch requests and background startup failures during pre-launch updates.

- New launches queue independently of background checks; completed and cancelled intents retire promptly.
- Progress reconnects and resubmits the same intent after a Manager session replacement; terminal state is rechecked before launch to prevent duplicate execution.
- Exiting consumers hand off newly queued requests, launches take priority over periodic following, and consumer failures return their cause.
- Client Manager workspaces support Windows directory junctions and redirected directories.
- Background initialization failures return their cause and release the workspace lease. Older running backends and progress windows are identified explicitly after an executable update.
