## 中文

机体客户端包可以直接通过 Manager 安装，不需要修改临时解包目录中的文件。

- 安装器接受发布编译器生成的 `blueprint-availability.json` 和 `blueprint-availability.bin`，保留文件摘要、目标路径和所有权检查；不带这两份数据的旧包继续兼容。
- Manager 内嵌的机体模板带有统一框架声明。发布编译器先设置机体运行文件，再生成最终依赖与配置声明，避免把资源归档或程序 DLL 当作配置指纹输入。
- 符号对比按 INI 字段处理空格、注释和字段顺序，避免相同的原生地址／指令定义被误报冲突；真实值变化或重复字段继续拒绝。
- 冻结版检查同时核对 EXE 内嵌的安装器与模板，避免只修源码或某次启动的临时文件。

更新 Manager 后重新生成并安装机体客户端包。上述机体安装修复不更改机体、技能、奖池或玩家数据，也不重新执行服务端定义应用。

地图与任务导入也修正了闸门与过场的顺序：保护完成后先开放通道，再播放下一段原生过场。复用过场时，各阶段独立应用门状态。已有任务需重新编译并发布匹配的客户端包与服务端计划；玩家数据保持不变。

## English

Unit client packages install through Manager without editing files in its temporary extraction directory.

- The installer accepts the publication compiler's `blueprint-availability.json` and `blueprint-availability.bin` while retaining hash, target-path and ownership checks. Older packages without these files remain compatible.
- Manager embeds a template with the shared framework contract. Publication finalizes the unit payload fields before deriving dependency/configuration declarations, keeping resource archives and programme DLLs out of configuration fingerprints.
- Symbol comparison handles INI spacing, comments and key order without reporting identical native definitions as conflicts. Changed values and duplicate keys remain rejected.
- Frozen-executable checks inspect the actual embedded installer and template, covering packaging as well as source behavior.

Update Manager, regenerate the unit client package and install it. The unit installation fix changes no unit, skill, prize pool or player data and does not reapply server definitions.

Map and mission import also applies gate changes before entry cinematics: the passage opens after protection succeeds, keeping the door out of the next camera path. Reused cinematics retain separate phase bindings. Rebuild existing missions and publish the matching client package and server plan; player data is preserved.
