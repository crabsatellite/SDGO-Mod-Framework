# 服主整合包更新

[English](owner-updates.md) · [返回功能目录](../README.zh-CN.md) · [统一 Mod Manager](mod-manager.zh-CN.md)

## 作用与维护边界

官方整合包提供一套基础搭配。服主开始 DIY 后，配置、脚本、素材、兼容性、访问权限与发布版本由服主维护。
Manager 提供审阅、打包和校验交付能力，无法判断任意自定义组合能否正常配合。服主应先检查自己的客户端与服务端组合，再发布给玩家。

更新路径为：上游发布 → 服主审阅 → 服主确认版本 → 玩家更新。调整 Manager 程序上游不会改变玩家绑定的负责人。

## 选择维护方式

打开「更新」→「整合包维护与服主发布」，选择已登记目录，保存维护方式。

| 维护方式 | 运行文件更新行为 |
| --- | --- |
| 基础整合包 | 按所选 Stable／Beta 通道接受兼容的上游运行更新。 |
| 服主 DIY | 保留自行维护的运行文件；采用上游组件前逐项审阅、明确选择。 |
| 玩家 | 只检查并安装绑定服主确认的整合包；适用于客户端目录。 |

没有明确维护选择的目录默认跟随基础整合包，已有 Mod 安装也使用这一默认值。
旧版自动套用的 DIY 状态，如没有维护声明、明确选择或发布设置，会迁回这个默认值。
需要接管维护时，明确选择并保存「服主 DIY」。已有明确选择和玩家负责人绑定会保留。
本地 DIY 标记在切换 Manager 工作区后仍有效。明确切回基础模式会解除负责人绑定，并允许上游运行更新；保存维护方式本身不会立即替换文件。

DIY 安装应先使用支持维护方式的 Manager。从不理解这些模式的旧 Manager 升级时，先只更换 Manager 程序。
受保护目录只接受声明支持服主更新协议的兼容程序发布。

## 审阅上游组件

「程序上游」填写兼容的 GitHub `owner/repository`，发布身份和包清单必须与该仓库一致。
这个设置控制 Manager／程序发布，与服主整合包的来源独立。

在 DIY 模式先检查上游版本，再点击「预览上游差异」。展开组件查看变化的文件，勾选需要的组件，点击「采用所选组件」。
默认不勾选任何组件。确认只适用于当前预览，输入变化后必须重新审阅。未选组件与已声明的独立配置保留；
选中的程序和脚本文件采用上游版本。较新的 Manager 可以审阅较旧的上游组件，不会因此降级 Manager 本身。

## 发布服主整合包

1. 选择服主的客户端目录，保存为「服主 DIY」。
2. 填写整合包名称、位于游戏目录之外的专用发布目录，以及玩家读取地址。
   地址可为 HTTPS 的 `owner-feed.json`，或 `git+https://git.example.org/team/client.git#main`。
   多个地址必须属于同一发布者并提供相同内容。
3. 使用 Git 发布时填写 HTTPS 仓库和分支，Manager 复用本机已有 Git 凭据，发布者需要写入权限。
   专用工作区必须干净，已有历史只做快进更新。静态托管时留空 Git 仓库，由现有 HTTPS 站点提供发布目录；Manager 不启动公网托管服务。
4. 保存设置，点击「预览发布内容」，检查实际文件列表。需要额外共享自制素材时，填写相对于客户端的路径；内容与使用权限由服主负责。
5. 点击「确认发布并核验公开下载」。Manager 创建不可变整合包版本，原子更新清单，再从配置的玩家来源读回元数据与包文件。
   实际读回通过后才显示发布成功。「重试推送／核对已有发布」复用当前版本，不会额外生成新版本。

整合包版本号与 Manager 版本独立。发布核验失败时，玩家继续使用已有版本。不要覆盖已发布 ZIP，或用同一版本号替换为另一份内容。

包内包含框架、公开 Mod、共享配置、摘要验证过的生成素材和明确声明的自制素材。
原版游戏程序与完整原生归档仅核对基础指纹，不随此包分发；玩家仍需使用服主提供的客户端包或更新获得兼容基础。

登录与画面设置、数据库、凭据、私人生日／账号名单、仅本地 Mod、开发诊断、日志和本地安装收据不进入玩家包。
共享 `sdgo/sdgo.ini` 仅投影公开 Mod／功能／分类设置，保留无关的本地设置。启用的扩展必须具有有效分发声明。
限制为 10,000 个文件、压缩后 128 MiB、展开后 512 MiB、单文件 64 MiB。

## 玩家绑定与更新

在「跟随负责人」填写服主地址，点击「查看发布者」，核对名称与发布者后确认绑定。
服主提供的客户端包也可携带不含凭据的 `sdgo/owner-source.json` 绑定。读取私有 Git 源时，每位读取者需要自己已有的 Git HTTPS 访问权限；
绑定与包内不保存服主凭据。仓库权限与来源可用性由服主负责。

可使用「检查负责人更新」「同步负责人版本」，或开启 Manager 运行期间自动跟随。
更新器固定发布者身份，安装前检查原版基础指纹、版本、SHA-256 与文件清单。来源不可用时保留当前版本；
可以尝试内容一致的备用源，有效但属于另一发布者的清单会被拒绝，不会静默切回官方整合包。

运行文件安装等待游戏关闭。写入前备份，失败或取消时回滚。退役清理只删除此前由该服主管理、且未经本地修改的文件；
个人文件和仅本地 Mod 留在本机。服主 DIY 维护目录不能用玩家同步命令覆盖。

## 无界面调用与排错

同一 Manager 程序可以接入服主自己的交付流程：

```text
"SDGO Mod Manager.exe" --check-owner-pack <游戏目录>
"SDGO Mod Manager.exe" --sync-owner-pack <游戏目录>
```

检查命令不修改运行文件。两条命令把结果写入 `sdgo/local-state/owner-updater/result.json`。
退出码：`0` 成功／已一致，`2` 等待关闭或参数无效，`3` 审计发现差异，`1` 错误。游戏运行时，一次性同步返回等待状态。

来源失败时检查 HTTPS 可用性和读取者的 Git 凭据／权限；发布者不匹配时先核对服主地址与绑定；
基础指纹不匹配时获取服主兼容的客户端基础；预览过期时重新预览；发布中断时重试核验已有版本。
Manager 退出会取消自己启动的 Git 进程树，不会停止游戏或无关的 Git 工作。
