# 服主配置与内容更新

[English](owner-updates.md) · [返回功能目录](../README.zh-CN.md) · [统一 Manager](mod-manager.zh-CN.md) · [归属与 SQL 边界](content-boundaries.zh-CN.md)

## 两条来源

玩家先取得兼容的原版客户端，再安装官方发布的 Manager。模组源提供 Manager、核心、Mod 程序和通用默认值；服主内容源提供 Mod 选择、精确版本、共享参数和全部自定义机体、素材及生成目录。原版程序和归档独立取得。

默认模组源为官方 GitHub Releases，也可导入兼容框架源配置，使用自己的 Git SSH/HTTPS 镜像。服主内容可经 Git SSH/HTTPS、HTTPS 清单与文件、离线目录或 ZIP 发布。完整客户端仓库和固定分支布局都是可选保存方式。

## 玩家首次安装

1. 将官方发布包中的 Manager 放入兼容客户端目录并启动；或在 Manager 添加该客户端目录。
2. 在「服主配置与内容更新」填写服主提供的地址，或输入离线 server-profile.json / profile-source.json 路径。
3. 点击「一键安装／跟随服主配置」。导入的配置同时绑定独立模组源和服主内容源，Manager 按锁定清单下载、校验并统一安装。
4. 双击 `GOnline.exe`。Manager 显示启动进度，同步锁定的模组程序和服主内容，校验安装完成后打开游戏。

配置绑定使用 sdgo/client-source.json 的 schema_version=3，内容清单使用 server-profile.json。Git 复用玩家已有的凭据、SSH 密钥和代理；不在绑定中保存密码或令牌。

下载页显示当前文件、已接收字节、已校验文件数量，以及暂存和安装阶段。慢速传输没有固定总时长限制，可随时取消并继续；已经校验的文件会复用，新的内容修订也会复用本地完全相同的文件。HTTPS 文件在服务器支持 Range 时保留并续传未完成部分；Git 逐个取得对象，保留已完成的对象与文件。

备用源必须提供同一份锁定清单和相同文件摘要。开始下载后不会因主源失败而切换到另一修订、另一套内容或官方默认配置。所有必需文件完整校验后才开始安装；缺失、损坏、取消或中断不算成功。安装过程失败会恢复原文件，不留下半套运行文件。

导入的绑定可选择同一发布者、同一传输方式的程序镜像，程序版本与通道仍由服主锁定。服主迁移传输方式时，Manager 按清单声明的新方式执行相同的完整性校验。

## 启动前更新

已绑定服主配置的玩家客户端由框架加载器接入现有 Manager 更新任务。首次安装配套的新版本 Manager 和加载器即可，无需单独的玩法 Mod、启动器或替换原版游戏程序。未绑定的客户端，以及明确接管为「服主 DIY」的编辑目录，保持普通启动方式。

每次启动会检查服主当前配置、下载所需程序和内容、提交已校验安装，再次核对远端修订；本地受管文件全部匹配后才打开游戏。官方程序源仍遵循服主的版本锁和共享参数。Manager 的定期跟随与启动检查分别工作，停止定期跟随不会跳过启动校验。

进度窗口显示检查、接收字节或文件数量、安装和启动阶段。慢速下载没有总时长或最低网速限制；错误时游戏保持关闭，可选择重试或取消，已经校验的下载会保留。一次待启动期间重复双击只合并为一次更新和启动。需要关闭已运行的游戏才能更新时，等待玩家正常退出；Manager 需要替换时沿用其重启事务，不结束玩家的游戏进程。

加载器先退出初始进程再替换文件，之后只接受绑定当前目录、来源和已校验收据的一次性短期启动许可，原始启动参数保持。缺少或使用过旧 Manager 时会提示安装配套版本；内容不完整不能作为离线成功放行。明确导入的离线配置会校验其指定的本地来源。
同时点击会共用已经校验的助手副本。助手程序由单一进程依次写入，后续点击不会在 Windows 启动该程序时再次替换它。

## 服主发布

在自己的客户端选择「服主 DIY」，通过 Manager 审阅并采用需要的模组版本，配置共享参数、生成机体和其他内容。首次导出配置档或采用不同程序版本后，先检查模组上游，再进入「发布服主配置与内容」。

填写客户端之外的绝对发布目录、玩家读取地址，以及需要额外下发的素材相对路径。生成器登记的内容和 Mod 声明的配置文件会自动纳入；不用手工维护程序 DLL 列表。

此前发布过的内容，以及已安装配置档收据登记的内容，在文件仍存在时继续纳入清单。接管已安装客户端不要求取得原来的私人生成器工作区；这些文件仍须通过内容与隐私校验，删除的文件按正常更新事务退役。

点击「保存并导出服主配置档」。留空 Git 发布地址时输出目录供已有 HTTPS 服务托管或离线传递；填写 Git SSH/HTTPS 发布地址与内容分支时，Manager 使用已有身份提交推送，并读回远端提交。HTTP 托管与镜像需由服主的既有服务提供，Manager 不启动公网文件服务器。

导出包含 server-profile.json、profile-source.json 和 content/。框架 DLL、Mod 身份和接口来自独立模组源，不能被内容覆盖。AI 目录等功能的通用程序随模组源分发，服主生成的 catalog.bin 仅进入内容源。相同内容再次导出复用修订号；共享参数或素材改变才增加内容修订，框架版本保持独立。

后续发布内容时，若仍安装已发布的程序版本，就沿用原程序锁；重启 Manager 或上游出现新版本，都不要求先升级程序。已安装的加载器、核心和所选 Mod 程序仍须与锁定包一致，修改过或未发布的程序会被拒绝。需要更换程序版本时，先明确审阅并采用，再让配置档跟随。Git 发布传输没有固定总时长限制，退出 Manager 会取消它所属的传输进程。

服主应将更新后的完整组合在自己的客户端／服务端验证后下发。玩家取得精确框架版本和 Mod 版本，不会独立追逐不兼容的最新版。

## 数据与安装安全

共享玩法参数和自定义资源随内容更新。个人登录、画面/FPS 和明确登记的个人字段保留；账号、库存、货币、密码、生日名单、数据库、日志和恢复数据留在本地或服务端。玩家安装不执行 SQL，也不迁移数据库。

所有来源使用同一暂存、摘要校验、恢复日志和安装事务。任一来源失败、版本不兼容、文件损坏或发布者变化时保留已有客户端。已绑定服主不能被另一服主静默替换；服主编辑目录也不能被玩家同步覆盖。原版基础文件不会在首次配置导入时被当成退役文件删除。

内容修订不能自动回退，同一修订不能替换成不同字节。已管理文件的退役走现有隔离／恢复流程。私有源的访问控制不等于可以下发私人名单或数据库。

## 排错

检查来源时核对原版版本、框架锁定版本、服主配置修订与实际安装状态。Git 来源失败应检查当前读取者的已有权限；HTTPS 来源失败检查托管端是否提供完整清单和文件。镜像必须提供相同身份及字节。

Windows 上的 Manager Git 传输支持较深的安装和工作区路径。已有 SSH 身份和凭据助手会保留，长路径支持仅作用于 Manager 所属的 Git 命令。

内容更新不要求重做原版客户端。若提示原版不兼容，应取得服主明确支持的客户端底包。游戏正在运行时正常退出后重试；安装中断使用页面的恢复入口。
