# 商城中文汉化（Beta）

`shop_localization` 是独立客户端 Mod，在 **SDGO Mod Manager** 中管理。
它翻译商城列表、悬停详情、购买和赠送页面的商品名称、说明、用法与销售选项；
0.1.1 补上商城设计图、普通扭蛋等公共机体预览的左上角名称。
与原有 `shop_labels` 租赁/永久标签修复分别注册，可以分别开关。

## 安装和使用

1. 客户端先安装基础框架，关闭目标游戏副本。
2. 打开 Mod Manager，选择该客户端，用「导入客户端配置包」导入 `SDGO-ShopLocalization-*.zip`。
3. 在「游戏功能」找到「商城中文汉化」，启用后按需要设置商品名称、说明和选项三个范围。
4. 正常启动游戏。切换开关、更新词典或导入新的商品显示配置后需重启客户端。

没有额外配置 EXE、网页服务或玩家指令。Manager 的“复制给 AI”会说明组件位置、开关、机制和验收边界，
Bug 报告入口仍使用项目统一仓库。保存或导入成功不代表游戏画面已经人工验收。

## 新增商品必须有中文

服主在 Manager 左侧「商城商品」选择原生物品后，先填「新商品中文名称」才能新增。
可以同时保留 `MSA-001` 等型号；纯英文、纯代号或空白标题不能保存为新商品。
销售选项也必须有中文，租期/数量变化会按原生类别与实际数值生成对应标签。
Manager 的创建、修改、导入、发布以及原生应用工具都执行校验。

旧工作区可以继续打开，不会重置或删除数据。旧商品若缺中文，先补齐再修改/发布，或者将其下架删除。
每次应用后，点击「导出玩家更新包」分发配套数据。朋友在自己的 Manager 导入这个 ZIP，
以后仍用原启动器；包里只有商城客户端模块、中文字典、显示定义、符号和哈希，没有 SQL 密码或服主目录。
朋友也可再次导出同一包。

新增父商品需要客户端的原生展示记录。汉化 Mod 使用原生分配器与表注册函数追加明确声明的显示记录，
复用现有模板图片，保留原表；收到类别、价格、币种和期限均匹配的本批原生商城回复后才显示服主中文标题。
核对状态只在当次列表、悬停或购买/赠送渲染中有效，不跨页面缓存旧验证结果。

## 翻译与数据边界

现有词条由精确编号关联和人工翻译组成；英文、泰文、韩文说明按可见原句翻译。
本机对应资料已核对 3299 个物品类别和 2489 条商城父商品展示记录，词典含 12757 条精确对照；
已知名称、说明、用法无待译缺口，原生型号标识和裸数字保留。覆盖统计见
[检查记录](investigations/shop-localization-coverage.json)，它不包含原始私有表。
原资料里的测试占位、损坏和截断会明确标注；无法核对官方专名的创意标题标注直译，不补造属性。
型号、数量、价格、百分比与原文限定保留。未来任意未登记文字仍按原文显示，新增商品的中文必填校验另行保证。

只在已核对字节的商城文字调用点和公共 `UnitNameStatic` 标题调用点替换 Unicode 输出。
公共标题来自机体记录的名称字段，也用于工厂、合成及扭蛋预览；它跟随「汉化商品与机体预览名称」开关。
这次截图中的 `BUILD STRIKE GUNDAM (ENHANCED...)` 与 `JEGAN (TYPE R)` 词典本来已有译文，
漏的是公共预览控件的调用白名单。0.1.1 补上该精确调用点，没有增加全局翻译 Hook。
不改价格、币种、租期、结算、SQL、仓库或已购记录，
也不重写 GPackData。未知宿主或损坏词典拒绝启用。原生新增展示记录发生异常或冲突时隔离失败，不覆盖已有记录。
汉化开关影响通用词典；服主已经提供的中文商品名继续作为商品内容显示。

## 手动测试

- 检查机体、设计图、副官、战斗道具、涂装、贴纸、战舰和礼包的列表名、悬停说明、购买/赠送标题。
- 在商城选中创世强袭高达设计图、普通扭蛋选中 `JEGAN (TYPE R)`，检查左上角预览名称为中文。
- 切换其他机体验证预览标题随选择更新；关闭名称汉化并重启后恢复原文，聊天和数字价格不应被替换。
- 截图里的决斗高达突击护甲/暴风高达，租期仍应明确为 7 天；GB/MB 和价格不应改变。
- 在 Manager 新增一个中文测试商品并应用，重启客户端后查看其中文标题和模板图片；再改价导出更新包。
- 用旧显示配置连接改价后的商品时，不应错误套用旧自定义标题；重新分发后再显示完整新内容。
- 关闭汉化并重启可回到原生语言；原版资料和玩家物品仍保留。

真人画面、购买扣款和发货由用户手动验收；自动检查使用实际 DLL、原生 ABI 模拟对象、隔离 SQL 和 Manager 包接口。
