# 异常断线登录恢复

[English](login-recovery.md) · [返回功能目录](../README.zh-CN.md)

## 作用

异常断线后重新登录时，原服可能判定“账号已在线”而拒绝登录，客户端也可能一直停在登录等待。
`login_recovery` 处理这种情况：原生登录已验证身份并清理旧会话后，
先通知旧 Agent 连接退出，再在同一请求内重新执行一次原生认证。

正常登录、密码错误、封禁及其他认证拒绝沿用原处理。该修复不创建账号，不修改机体、货币或凭据，也不处理无关的网络中断。

`login_recovery_client` 补充客户端等待流程：登录无进展或连接断开时，使用原生退出与重连流程，
最多自动重试三次。每阶段默认等待 15 秒，退避为 1、2、4 秒，总预算为 90 秒。
昵称等需要玩家操作的页面暂停计时。密码错误、封禁和其他明确拒绝停止重试；按 Escape 可取消。
恢复耗尽后重新显示原生登录输入界面，玩家可以再次输入并登录。

连接重建前会丢弃旧连接排队的回包；同一请求仍在等待时，重复提交不会替换当前身份。
客户端只在进程内暂存这次登录的用户名及密码摘要，成功、取消或结束时清除，不写入文件和日志。

## 使用

将配套框架服务端文件安装到 WorldServer，并重启该宿主。在 Mod Manager 的「修复归档」中查看
“异常断线登录恢复”。修复默认启用，没有玩法参数；停用也需要重启相应宿主。
玩家使用服主提供的客户端包或更新，无需额外运行玩家程序。
客户端组件安装后重启游戏生效，在修复归档中显示为“登录等待自动恢复”，没有需要填写的参数。

## 日志

`native authenticated old-session recovery active` 表示修复已加载。
`retrying authentication once in the same request` 表示进入了恢复分支，不等于后续登录已经成功。
日志不记录密码或登录封包。
客户端的 `native reconnect` 和 `native retry request` 记录实际恢复动作，
`interactive native login page restored` 表示原生输入控件已重新创建；
`native login completed into usable lobby/hangar` 才表示登录流程已离开等待阶段。

若仍反复登录失败，继续检查原生登录结果及 Agent 连接。宿主不匹配或符号校验失败时，修复不会启用。

## 开发者说明

支持的宿主为 `WorldServer-548A86E3-0010C000`。Hook 仅位于原生重复会话分支已验证身份并调用
`ForceDisconnetUserDB` 之后。修复把原有八字节 `0x1F4B` Agent 退出通知放在再次认证之前，
避免新会话获准后又收到按账号发送的旧退出通知。每个请求最多重试一次，第二次冲突沿用原失败路径。

原生请求使用 x86 `thiscall`，没有栈参数。指令 Hook 保留通用寄存器、栈及 FP/SIMD 状态，
并返回原生认证调用点继续执行。原生 SQL 过程及起始资料策略继续负责认证和账号初始化。

客户端沿用原生退出与重连业务命令，重新建立网络对象及登录界面，退出 Gate 时由原生释放流程清空
待处理请求。重连业务命令本身并不保证执行 Gate 的完整释放，因此修复还会在重新开放登录界面前，
调用原生方法移除 `REQ_LOCAL_LOGIN_USER`。原生请求超时只标记时间，不会自动移除请求锁，
因此只再次发送封包不足以恢复输入。
界面恢复必须匹配本次重新初始化的 Gate 所有者；重建过程中仍可见的旧控件不能作为完成依据。
初始化上下文可以合法为空，不能把空上下文当作界面失败。认证回包也不等于资料加载完成，
客户端以实际进入大厅或机库判定成功。

频道选择读取当前频道界面及真实的加载、可见和请求状态。频道数据未齐、加入请求未完成时继续计时；
已就绪的 VS、任务和战队频道选择暂停计时。Gate 与频道界面使用不同对象，切换后不保留旧 Gate 指针。
