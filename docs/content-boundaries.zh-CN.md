# 框架、服主内容与本地状态

[English](content-boundaries.md) · [Manager](mod-manager.zh-CN.md) · [服主发布](owner-updates.zh-CN.md)

## 设计原则

Manager 组合的是内容契约，不依赖某个服务器的完整客户端仓库或分支命名。玩家先取得兼容的原版客户端，再导入服主配置档；Manager 根据锁定清单从框架源取程序，从服主源取共享配置和自定义素材。

官方 Mod 列表描述可用程序。服主配置档决定实际选择、精确版本、共享参数和内容摘要。玩家不能各自选择“当前最新版”而产生不同的玩法组合。首次发布和后续更新使用同一解析、兼容性检查、暂存、恢复日志与安装事务。

| 归属 | 内容 | 发布范围 |
| --- | --- | --- |
| 通用框架 | Manager、核心、Mod 程序、接口、通用默认值、配置协议和 SQL 模板 | 框架源码及相应通道的程序包 |
| 服主共享内容 | Mod 选择／版本锁、共享参数、新增机体、模型贴图、生成目录 | 服主选择的内容源；可为私有 Git、HTTPS 或离线目录／包 |
| 服主服务端定义 | 新机体和商店的具体记录、奖励规则、生成的服务端数据计划 | 服主服务端维护流程；不随玩家配置档执行 |
| 私人及运行数据 | 密码、令牌、生日名单、真实账号、库存、货币、数据库、日志及恢复状态 | 留在对应的本地或服务端私有工作区，不下发玩家 |
| 原版基础及完整客户端备份 | 原版程序／归档，或已组合的完整快照 | 独立取得；服主可选保存完整备份，不是框架必需的发布源 |

私有内容源表示访问权限，不意味着其中应放入密码、生日名单或玩家数据库。客户端共享内容是可下发玩家的子集；服主的完整编辑工作区与共享内容导出分开。

## SQL 归属

`distribution/artifact-ownership.json` 逐项登记框架中的 SQL。通用 SQL 可以创建表、过程、触发器，也可以使用参数查询或维护当前服务器的数据；这些是框架实现代码，不是某个服务器的数据快照。

例如通用收藏初始化查询会读取当前数据库已有库存来建立本服务器的索引。查询模板可以发布；执行后得到的账号、解锁与库存记录不能随框架或玩家内容包发布。文件名中的 `owner/` 表示服主管理功能的通用实现，不表示里面可以保存本服实际记录。

服主编辑机体、商店或奖励后生成的具体 INSERT/UPDATE 计划属于服主服务端定义。它们沿用服务端预览、维护条件、事务和生效检查；玩家导入配置档不执行 SQL，也不迁移数据库。真实账号、库存及货币等运行数据不属于定义导出。

## 来源与安装

服主配置档同时包含原版版本要求、精确框架版本及摘要、选定 Mod、共享配置清单和自定义文件摘要。Git 只是传输适配器之一；HTTPS 清单／资源文件及离线目录使用相同配置契约、归属检查与安装器。

程序身份、DLL 和接口声明由框架源提供，服主源只修改声明的配置参数和内容文件。登录、画面／FPS 和明确登记的个人参数保留；共享玩法参数跟随服主。来源失败、摘要错误或依赖不满足时保留已有安装。

完整客户端快照可以由同一锁定清单组合后导出用于备份或首次发放。它是可选成品，不是另一份手工维护的配置真相；不能反过来覆盖已选择的框架来源。
