# 框架、服主内容与本地状态

[English](content-boundaries.md) · [返回功能目录](../README.zh-CN.md) · [Manager](mod-manager.zh-CN.md) · [服主发布](owner-updates.zh-CN.md)

## 设计原则

Manager 组合的是内容契约，不依赖某个服务器的完整客户端仓库或分支命名。玩家先取得兼容的原版客户端，再导入服主配置档；Manager 根据锁定清单从框架源取程序，从服主源取共享配置和自定义素材。

官方 Mod 列表描述可用程序。服主配置档决定实际选择、精确版本、共享参数和内容摘要。玩家不能各自选择“当前最新版”而产生不同的玩法组合。首次发布和后续更新使用同一解析、兼容性检查、暂存、恢复日志与安装事务。

启用[本服程序包](owner-programmes.zh-CN.md)的配置会将配套 Manager、官方基线和本服补丁一起锁定；内容层仍不含可执行文件。没有本服程序层的普通配置档保持原有 Manager 更新策略。

| 归属 | 内容 | 发布范围 |
| --- | --- | --- |
| 通用框架 | Manager、核心、Mod 程序、接口、通用默认值、配置协议和 SQL 模板 | 框架源码及相应通道的程序包 |
| 本服程序 | 明确允许向本服分发的客户端补丁及官方基线锁 | 独立本服程序源；源码保留私有，仅本机插件继续排除 |
| 服主共享内容 | Mod 选择／版本锁、共享参数、新增机体、模型贴图、生成目录 | 服主选择的内容源；可为私有 Git、HTTPS 或离线目录／包 |
| 服主服务端定义 | 新机体和商店的具体记录、奖励规则、生成的服务端数据计划 | 服主服务端维护流程；不随玩家配置档执行 |
| 私人及运行数据 | 密码、令牌、生日名单、真实账号、库存、货币、数据库、日志及恢复状态 | 留在对应的本地或服务端私有工作区，不下发玩家 |
| 原版基础及完整客户端备份 | 原版程序／归档，或已组合的完整快照 | 独立取得；服主可选保存完整备份，不是框架必需的发布源 |

私有内容源表示访问权限，不意味着其中应放入密码、生日名单或玩家数据库。客户端共享内容是可下发玩家的子集；服主的完整编辑工作区与共享内容导出分开。

## 自定义文件的导入入口

先看包内根清单与协议，不能只看 `.zip` 扩展名。作者输入、编辑配置和玩家运行包是不同产物：

| 拿到的内容 | 识别与 Manager 入口 | 还需完成什么 |
|---|---|---|
| 机体原始 RAR/ZIP、`sdgo.unit-project` 制作项目 | [机体导入](unit-import.zh-CN.md)，解析／保存项目 | 补定义、预览与确认；新技能的完整发布走[技能组合例子](unit-skill-import.zh-CN.md) |
| 已编译机体 `publication/` | `server-plan.json` 与 `package/`；机体面板“批量阵容服务端应用” | 服务端预检、维护、应用、读回；安装匹配客户端包 |
| `.opack` | 根 `operator-pack.json`，`sdgo.operator-pack`；[副官分享包预览](operator-pack-protocol.zh-CN.md#从零组合一个非敏感分享包) | 创建草稿后另做服务端、客户端、能力运行及可选商城操作 |
| 地图制作文件夹 | 根 `map.json`，`sdgo.map-package`；[地图与任务导入](map-import.zh-CN.md#不依赖现成地图素材的最小案例) | 登记后编译，安装客户端并检查／应用服务端 |
| 扭蛋语义 JSON | 含 `units`、`fixed_machines`、`custom_machines`；[扭蛋机编辑器](capsule-catalog.zh-CN.md#新增训练机池并交换配置) | 保留来源身份与候选规则，编译并应用两端 |
| 商城配置 JSON／作者样例 ZIP | 含 `catalog_id`、`products`；[逐类模板](../examples/shop/README.zh-CN.md)解压后在“商城商品”导入 `shop.json` | 同工作区导入草稿，再明确上架并应用；样例默认未启用，不导入模型 |
| AI 分级规则 JSON | `exclude`、`levels`、`templates`；[AI 机体清单](ai-catalog.zh-CN.md)的开发信息 | 对当前目录检查、生成并把同版目录安装到两端；规则不是 AI 程序 |
| 任务行为 `profile.bin` | [任务行为](mission-behavior.zh-CN.md)页面导入匹配 profile | 预检完整客户端／Battle 组，配对应用并按提示重启 |
| `server-profile.json` / `profile-source.json` | [服主配置与内容更新](owner-updates.zh-CN.md#用离线目录交付训练内容) | 玩家解析版本锁、下载和校验，再安装；不执行服务端 SQL |
| 工具生成的玩家运行 ZIP | “游戏功能”中选择目标客户端，点击“导入配置包” | 检查清单、依赖及文件归属；原始 `.opack`、地图文件夹、商城 JSON 或 `.shop-authoring.zip` 不能改名后放进此入口 |

FRP 端点使用[连接配置示例](frp-distribution.zh-CN.md)，海报、头像和音频则使用各自作者工具的素材入口。
单张图、单份规则或单个原生记录不会隐式创建它引用的机体、商品、任务或数据库定义。

虚构的完整链路可以是：先导入“训练测试机”及技能，读回两端定义；再明确选择将它加入“训练机池”或
创建“训练机使用权”商品；另导入作者自绘的“训练副官”；最后发布这一组合的共享内容和版本锁。
每一步都保留上一步的稳定身份，不复制其他服主的内容作为模板。选择“不新增获取方式”也是有效的发布决定。

源码中的 `owner/` 和带有 `pending`、`authoring` 的兼容字段不代表某个服主的数据，更不等于全局运行能力判定。
判断支持范围应追到当前入口的校验器、编译器和消费者。遇到限制时列出具体字段、依赖、目标版本或缺少的处理器，
不要默认删技能、丢形态、套用别人的图片，或根据旧草稿状态断言完整协议不支持。

## SQL 归属

`distribution/artifact-ownership.json` 逐项登记框架中的 SQL。通用 SQL 可以创建表、过程、触发器，也可以使用参数查询或维护当前服务器的数据；这些是框架实现代码，不是某个服务器的数据快照。

例如通用收藏初始化查询会读取当前数据库已有库存来建立本服务器的索引。查询模板可以发布；执行后得到的账号、解锁与库存记录不能随框架或玩家内容包发布。文件名中的 `owner/` 表示服主管理功能的通用实现，不表示里面可以保存本服实际记录。

服主编辑机体、商店或奖励后生成的具体 INSERT/UPDATE 计划属于服主服务端定义。它们沿用服务端预览、维护条件、事务和生效检查；玩家导入配置档不执行 SQL，也不迁移数据库。真实账号、库存及货币等运行数据不属于定义导出。

## 来源与安装

服主配置档同时包含原版版本要求、精确框架版本及摘要、选定 Mod、共享配置清单和自定义文件摘要。Git 只是传输适配器之一；HTTPS 清单／资源文件及离线目录使用相同配置契约、归属检查与安装器。

官方与本服的程序身份、DLL 和接口声明分别由对应程序源提供，内容源只修改声明的配置参数和素材。登录、画面／FPS 和明确登记的个人参数保留；共享玩法参数跟随服主。来源失败、摘要错误或依赖不满足时保留已有安装。

完整客户端快照可以由同一锁定清单组合后导出用于备份或首次发放。它是可选成品，不是另一份手工维护的配置真相；不能反过来覆盖已选择的框架来源。
