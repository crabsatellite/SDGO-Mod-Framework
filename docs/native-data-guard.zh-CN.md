# 原生数据与生命周期崩溃修复

[English](native-data-guard.md) · [功能目录](../README.zh-CN.md)

## 作用

客户端 Mod `native_data_guard` 保护原生数据读取、正确持有机体管理延迟消息，并修复异常报告上下文：

- 浮游炮挂点名称只接受 1–6 号索引。其他索引返回游戏原有的空结果，避免越过名称数组。
- 两种原生名称显示格式遇到缺失记录时显示“未命名”。已有名称继续使用原生记录。
- 机体信息刷新遇到缺失派生记录时沿用游戏已有的分母为零分支，保留默认百分比，不再读取空指针。
- 模型缺少可选变形数据时，基础模型继续完成原生载入和状态设置。
- 原生异常报告使用独立的栈回溯上下文；报告中的异常地址、访问类型、模块范围和寄存器来自回溯前的原始现场。
- 机体管理等待库存数据时，服务保存原生消息副本，不再持有消息分发器的临时对象。重复请求、服务复制和销毁都有各自明确的所有权；原版完成路径仍只入队一个副本，并释放服务持有的副本一次。

这些保护不会补齐缺失模型、添加机体、更改武器或调整战斗奖励。保护范围是上述数据路径；其他位置的客户端异常需要单独定位。

## 使用

安装服主提供的客户端包或更新。Mod 在支持的客户端上自动启用，统一 Mod Manager 的自动修复归档中可以查看；没有需要玩家调整的参数。安装或更新后重新启动客户端。

支持的客户端标识为 `GOnline-54BE1568-00C97000`。框架在启用前检查命名符号的原生指令。其他客户端版本或同一位置存在冲突补丁时，需要先核对兼容性。

## 日志

启用成功时，框架日志记录 `native data guards active`。缺失名称、信息记录和可选变形记录会输出有限警告；正常数据不会逐帧输出警告。发生原生异常时，框架日志会额外记录回溯前的原始寄存器和访问地址。

再次闪退时，保留当次原生异常日志、当前框架日志和上一份框架日志，再重新启动。核对会话和时间；复制来的客户端文件夹可能带有其他安装的历史异常记录。

## 开发者说明

原生浮游炮索引条件使用了“或”，使任意有符号索引都能进入数组读取。经过指令校验的两字节分支修正，让非法索引进入游戏已有的空结果分支。

名称保护只作用于两个已核对返回地址的显示调用者。静默预检查使用原生的 type-2/type-24 名称键计算；记录缺失时返回不可变的文本记录，文字位于第 13 字节。其他调用者及有效记录保留原生查询行为。

模型保护位于基础模型载入之后的可选变形记录读取处。记录为空时保留 x86 原生上下文，继续原有收尾流程；不会跳过整个加载任务，也不会把机体替换成另一台。

信息页保护位于派生记录返回后的第一个读取处。记录为空时只为被移位的原生读取提供一个零值记录，使后续代码进入游戏原有的默认百分比分支；有效记录和计算公式不变。

机体管理生命周期保护只作用于已核对的延迟消息槽。消息分发回调返回前先调用原生复制虚函数；服务复制时深拷贝这条自有消息；重复请求或服务销毁时释放仍挂起的副本。原版加载完成路径继续把消息复制进队列，并销毁服务持有的副本。

异常报告保护包装原生异常记录器，并只在该线程、该次记录期间把 `DBGHELP!StackWalk` 的可写 `ContextRecord` 指向独立副本。原生记录器继续执行原有的栈回溯和报告流程，但回溯不能再改写随后打印的寄存器。

`native_data_guard_actual_dll` 执行实际构建的 DLL 和站点跳板，并覆盖延迟消息保存、替换、服务复制、正常完成和销毁。安装本 Mod 后，原生 GameTest 的 bootstrap 还会调用宿主的挂点、名称格式和信息刷新函数，再继续认证、建房及战斗流程；信息刷新使用私有展示接收器核对原生默认百分比，不改写活机体或数据表。`SdgoNativeDataGuardGetStatusV1` 和 `V2` 保持原有观察器 ABI；`SdgoNativeDataGuardGetStatusV3` 追加原生延迟消息复制、替换、复制失败、原生完成次数和当前仍由服务持有的消息数。
