# 场景登记生命周期修复

[English](scene-lifecycle-fix.md) · [返回功能目录](../README.zh-CN.md)

修复场景对象切换到另一个区域后，偶发的清理闪退。

## 使用

`scene_lifecycle_fix` 是客户端自动修复，没有设置项，在 SDGO Mod Manager 的「修复归档」中列出。
安装服主提供的客户端包或更新后重启游戏即可，服务端无需配置。

本 Mod 只支持声明的原版客户端 build；安装钩子前会核对 host profile、所需原生符号和完整的函数指纹，
客户端代码不一致时拒绝安装，不做猜测性修改。日志报告缺少符号或指纹不匹配时，请使用服主提供的受支持客户端；
在该客户端上仍然失败时，请在问题反馈中附上客户端日志。

## 开发者说明

原版客户端把场景对象切换到另一个空间节点时，先从旧节点的链表中移除对象，再为目标节点分配新的链表节点。
原生分配失败时，对象仍可能指向旧所有者，而旧所有者已经不再登记它，后续清理就会访问已经失效的所有者。

本 Mod 先用原生分配器准备一个尚未挂入链表的目标节点；分配成功后，才移除旧登记、追加新节点并设置新所有者。
正常移动仍得到原生的链表形状和所有权结果，并保留以下原生行为：

- 目标与当前所有者相同时不做任何修改。
- 继续使用原生链表分配、移除和所有者设置函数。
- 原生分配异常原样向外传播。
- 分配器返回空值时，旧登记和旧所有者保持不变。
- 原生链表容量错误保留原消息和异常路径。

`SdgoSceneLifecycleGetStatusV1` 提供只读计数：切换调用、分配尝试、成功提交、同所有者调用、原本无所有者的对象、
空分配结果和容量错误。该接口不修改场景状态，也不提供测试专用的控制路径。
