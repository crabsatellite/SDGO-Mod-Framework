# 场景登记生命周期修复

[English](scene-lifecycle-fix.md) · [返回功能索引](../README.zh-CN.md)

原版客户端把场景对象切换到另一个空间节点时，会先从旧节点的链表中移除对象，
再为目标节点分配新的链表节点。如果原生分配失败，对象仍可能指向旧所有者，
但旧所有者已经不再登记它；后续清理就可能继续访问已经失效的所有者。

`scene_lifecycle_fix` 先用原生分配器准备一个尚未挂入链表的目标节点。分配成功后，
才移除旧登记、追加新节点并设置新所有者。正常移动仍保持原生链表形状和所有权结果。

## 使用与兼容性

客户端组件自动启用，没有配置项。安装服主提供的客户端包或更新后重启游戏即可，
服务端无需配置。

本 Mod 只支持声明的原版客户端 build。安装钩子前会核对 host profile、所需原生符号和
完整的切换所有者函数指纹。客户端代码不一致时会拒绝安装，不会猜测性修改。

## 保留的原生行为

- 目标与当前所有者相同时仍然不做任何修改。
- 继续使用原生链表分配、移除和所有者设置函数。
- 原生分配异常保持原样向外传播。
- 分配器返回空值时，旧登记和旧所有者保持不变。
- 原生链表容量错误保留原消息和异常路径。

这个修复关闭的是一个确定存在的所有权缺口，并不表示所有原生场景清理崩溃都由它造成。

## 开发者诊断

`SdgoSceneLifecycleGetStatusV1` 提供只读计数，包括切换调用、分配尝试、成功提交、
同所有者调用、原本无所有者的对象、空分配结果和容量错误。该接口不会修改场景状态，
也不提供测试专用控制路径。

如果日志报告缺少符号或函数指纹不匹配，请使用服主提供的受支持原版客户端 build。
在该 build 上仍然失败时，请在问题反馈中附上客户端日志。
