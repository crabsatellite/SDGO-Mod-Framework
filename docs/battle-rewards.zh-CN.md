# 战斗贡献奖励

此功能已接入 BattleServer 的原生最终结算：按胜负、击杀、实际伤害、助攻、任务小怪与 Boss 贡献
计算 GB/MB；对战 MVP 另有 MB 奖励。服主在 Manager 中调整倍率，玩家沿用原客户端和启动器，无需安装客户端 Mod。

[English](battle-rewards.md) · [完整规则与初始数值](battle-reward-design.zh-CN.md)

可选的[MB 轻度养成](solo-mb-progression.zh-CN.md)提供任务保底及可配置的日周目标，默认关闭。
公共初始值为每日首局 100 MB、每日三局额外 400 MB、每周十二局额外 1,000 MB；升级保留已有服主配置。

## 人数倍率与聚会奖励

在「战斗奖励 → 人数倍率与周期聚会奖励」中，可启用一至十二名真人分别对应的倍率表。
未启用自定义表时沿用 `1.1^(有效真人数−1)`。AI 和观战者不计数；人数倍率与基础、活动和时长系数
一起作用于正常贡献奖励，固定补给另算。

聚会奖励默认关闭，不附带公共高额发币预设。添加规则后设置真人门槛、对战/任务范围、每场/每日首次/
每周首次和固定 GB/MB，再启用。全组可设置最低有效秒数、是否必须有实际贡献及重置时区。
领取人及计数真人都须满足参与要求；数据来自服务器原生结算，网页预览不能上报战绩领钱。

领取资格按账号分别判断：已领过的朋友仍可一起玩，新加入的朋友可领取自己的份额。
共用钱包的 BattleServer 按「账号、规则编号、周期」去重。每日本地零点、每周一本地零点重置，
以本局原始结束时间归属周期；工作器重试不重复发放。编辑金额时保留规则编号即可保留已领取状态，
换新编号代表新增另一份奖励。

聚会固定奖励不乘任何倍率。GB 和 MB 在同一事务内调用原生钱包过程，一项失败会回滚两项及领取记录。
这笔 GB 单独入账，不受正常结算字段 65,535 上限限制。在线余额沿原生消息刷新，离线者正常登录或查询商城刷新。
启用前安装配套 Battle Mod 与 Manager/钱包服务。聚会使用 v3 原生参战快照；旧 v1/v2 待处理作业继续按原规则处理，
不会推测或补造聚会资格。

## 规则与已有双倍功能

```text
最终 GB/MB = 向下取整一次(
  一倍基础和贡献奖励 × 服主基础倍率 × 双倍时段系数 × 1.1^(有效真人数−1) × 有效参战时长系数
)
```

带 AI 的对战与纯真人对战同档。真人数量按整场有效参战账号计数，AI 和观战者不算。
例如基础十倍、双倍时段、四名真人为 `10 × 2 × 1.331 = 26.62` 倍。

双倍时段由已启用的 `daily_rewards` 提供。奖励 Mod 在它之后处理 GB，使用独立的一倍值重算，
不对已经乘过双倍或改过十倍的旧表值再乘一次；MB 使用相同活动系数。角色与机体经验继续由
原来的双倍组件处理。未加载该组件时活动系数为 1。改其时段后按该组件要求重启服务；本功能的
基础倍率和奖励数值可以在 Manager 奖励面板热更新，不需要重启 BattleServer。

默认三分钟达到完整时长系数。计算规则的最低有效时长为 30 秒，**仍须通过游戏原生资格检查**；
原生代码拦截的短局、无效或退出资格不会被本功能绕过。击杀为零仍保留符合资格的胜负保底。
例如有效参战 45 秒时，时长系数为 `45 / 180 = 25%`；短局的两三千 GB 本身不代表奖励服务失联。
助攻按该目标一条生命中至少 10% 的实际 HP 损失计，最后一击获得击杀、不再重复计助攻。
任务 Boss 以服主当前数据库的任务/NPC 身份映射判定，按有效贡献分配，不用外观或最后一击猜测。

同样三分钟、四名真人、十倍＋双倍：任务示例为 4,871 GB/13 MB，对战胜利示例为
21,296 GB/90 MB；同一对战同时为 MVP 则为 26,620 GB/250 MB。具体条件和全部封顶值见完整规则。

## 统一 Manager 中安装和管理

打开 **SDGO Mod Manager.exe**，进入“战斗奖励”。不再使用独立奖励网页或启动脚本，也无需安装 Python。

1. 在目录设置中选择原有奖励配置目录、原生服务器配置文件、要更新的对战服务器，以及已解压的框架/奖励包。
2. 点击“检查安装 / 更新”，先处理阻断项。自行结束相关对局并关闭要更新的那个服务器后，应用刚才检查的计划。
3. 安装保留符号、配置和恢复收据，只增加本功能的版本化钱包对象，不修改原生钱包过程或玩家余额。
4. 从同一面板启动 Manager 拥有的钱包服务，再按原方式启动对战服务器。倍率、规则和预览都在本面板管理。

更换目录或服务器前停止本 Manager 的工作器；不会停止旧入口登记的外部工作器，旧部署需先迁移。
页面只有在当前策略、原生结算和钱包心跳均确认时才显示连接。原生 GB 字段上限为 65,535；
当前策略的安全倍率上限由运行时报告，超范围会拒绝，不静默截断。完整使用见[统一 Manager](mod-manager.zh-CN.md)。

Manager 负责异步钱包服务，运行期间应保持它开启。它会记住已启用的服务，启动时恢复，数据库连接中断时自动重连。
工作器首次验证原生钱包身份后，将这个身份与短期在线心跳分开保存。
之后 Manager 暂停、更新或重启时，Battle 仍按本局快照计算贡献奖励并保存待发作业，不因短暂失联退回原版收益。
钱包尚未初始化、身份不匹配、策略无效或待发记录无法可靠写入时仍拒绝自定义结算，并报告具体原因。
升级时先更新 Manager 并启动钱包服务，再在对应 BattleServer 空闲关闭后更新服务端 Mod。

对战服务器端口可连接不等于钱包已恢复。面板失联时，已落盘的奖励保留；恢复同一工作区后自动处理队列，
无需等待深夜批次。需要无人值守时，将现有 Manager 和原 workspace 加入操作系统的正常启动配置。

## 入账、断线和恢复

GB 使用原来的 World/钱包通路，替换最终金额后正常入账与显示，不另发第二份完整 GB。
原生结算动画会逐项累加基础 GB 和旧表加成，跳过动画则直接显示总额；两条显示路径必须一致。
奖励 Mod 将本局完整 GB 放入原生基础奖励行，并清零已被新规则替代的旧 GB 加成行。
因此该行包含胜负、贡献、MVP、倍率和时长折算后的完整金额，不再代表旧奖励表中的单独保底。
角色/机体经验明细以及另行入账的其他系统奖励不由这一显示修正改写。
MB 先进入持久队列，调用原生 `sp_PocketGC_IO` 并以本局/账号/计划摘要去重。工作器提交后重读当前 MB，
以已有 `0x064B` 消息通知在线客户端；不把历史回执里的旧余额重放到玩家界面。

工作器响应丢失后可重试，不会重复加 MB。已经断线或会话被回收时，保留到账结果，跳过旧路由通知，
由下次正常登录/商店现金查询刷新。工作器中断时，Manager 奖励面板会显示失联；修复并启动相同 workspace 后
继续处理原队列，不要删除 runtime 中的待处理作业或数据库回执。
Windows 原生发布者短暂占用文件时，工作器会有限重试读取和归档；记录仍无法处理时报告错误，不把失败当成已发放。
钱包身份绑定不会在重连时静默改到另一个数据库，也不会放宽账号、策略摘要或数据库收据的去重校验。

需要停止时，在奖励面板点击“停止本 Manager 的钱包服务”。它只停止本 Manager 自己记录的工作器，不会按进程名批量关闭。

## 历史 GB 补偿

缺少完整战斗快照时，管理员可以用相同 GB 规则下、条件相近的正常结算样本，对已核实的战斗入账做平均值补偿。
旧版已经降级且没有保存应发记录的场次不能精确重建；正常的短局折算不能仅因金额较低就被当成漏发。
先将各样本除以其活动倍率，计算精确平均值，再乘受影响场次的活动倍率，最后向下取整一次。
每局只补 `max(0, 目标值 − 已到账 GB)`，原本高于平均值的奖励不扣回。这是管理补偿，不能声称精确重算了伤害、助攻或 MVP。

源码和奖励管理工具包提供维护命令，需要 Python 3.10+、`pyodbc` 和 SQL Server ODBC 驱动。
按[补偿计划格式](battle-reward-design.zh-CN.md#gb-补偿计划)准备并核对本地私有计划，然后预览：

```powershell
python tools/recover_battle_reward_gb.py --plan "D:\SDGO-Owner\Recovery\gb-plan.json" --server-ini "D:\SDGO\Server\WorldServer\WorldServer.ini"
```

预览只检查计算，不写数据库。确认计划后加 `--apply` 执行。执行时核实数据库文件范围、钱包身份、正常样本的
成功回执与原生入账记录，再通过未改动的 `sp_PocketGP_IO` 补差。整个批次使用事务；每笔原始入账都有不可重复
补偿的数据库收据，重复运行同一计划不会再次发放，改写已经执行的补偿条件会被拒绝。保留私有计划和数据库收据，
补偿后可通过正常重新登录刷新游戏中的 GB 余额。

## 禁用与卸载

退出相关对局、关闭对应 BattleServer，在 Manager 中关闭本功能（Battle contribution rewards）后再启动服务器。
需要移除时，用安装器先看卸载计划，再加 `--apply`：

```powershell
python tools/install_battle_rewards.py --battle-dir "D:\SDGO\Server\BattleServer1" --workspace "D:\SDGO-Owner\Rewards" --uninstall
python tools/install_battle_rewards.py --battle-dir "D:\SDGO\Server\BattleServer1" --workspace "D:\SDGO-Owner\Rewards" --uninstall --apply
```

只归档该 Mod，保留公共框架、其他 Mod、数据库账目、配置与队列。未确认完的到账作业先处理完，
不要通过删除回执来“重置奖励”。重新开启服务器后恢复原生奖励路径，已有奖励不会被回滚。

## 开发与测试

在 Windows 源码目录安装 Visual Studio C++ 工具后：

```powershell
cmake -S . -B build -A Win32
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

默认测试使用真实 core/Mod DLL、合成原生帧和隔离账本，不需要生产数据库。可选的真实 SQL 测试需要原生服务器 INI
和创建/删除临时数据库的权限，只在新建的隔离库中复制原生钱包过程。规则计算的测试命令见[规则文档](battle-reward-design.zh-CN.md#复现)。
