# 对战模式 AI 玩家

[English](pvp-ai.md) · [返回功能目录](../README.zh-CN.md)

在双阵营 PvP 房间标题里写 `!ai`，即可加入 AI 对手和队友，使用原有的战斗、计分、复活和观战功能。
支持普通、死亡竞赛、Grid、队长和 Tag 模式。

![对战 AI 的队友与敌人交战](pvp-ai-demo.webp)

## 安装

两部分都包含在完整框架包中；玩家通过服主提供的客户端包或更新获得 `match_ai`。

| mod | 安装位置 |
|---|---|
| `pvp_ai` | 对战服务器 |
| `match_ai` | 每个参战玩家的客户端 |

按[安装说明](setup.zh-CN.md#安装)安装，然后使用平常的启动器进入游戏。
对战服务器和所有参战客户端（包括房主）需使用同一版本的组件（`pvp_ai` 0.3.2、`match_ai` 0.1.6 或更新），
更新后重启相应程序。

## 使用

设置房间标题后，照常准备、开始；AI 在开局时加入。

### 房名指令

| 房间标题 | 效果 |
|---|---|
| `!ai coop` | 真人开局时自动跟房主同队，本方不补 AI，对面填满全房剩余名额 |
| `!ai coop fill` | 真人自动同队，然后双方补位；8 人房、3 名真人时为 3 真人 + 1 AI 对 4 AI |
| `!ai coop e4 a0` | 真人自动同队，精确加 4 个敌人，不加队友；3 名真人时为 3v4，剩 1 个空位 |
| `!ai versus fill` | 保留房间手选／随机分队，双方补位；与 `!ai fill` 相同 |
| `!ai` 或 `!ai fill` | 双方补满房间；8 人房通常为 4v4，真人占用的名额不重复补 AI |
| `!ai3` | 加 3 个敌方 AI |
| `!ai e* a0` 或 `!ai enemy` | 本方不加 AI，对面用 AI 填满剩余房间空位 |
| `!ai e* a*` | 与 `!ai fill` 相同 |
| `!ai e5 a0` | 精确加 5 个敌方 AI，不加 AI 队友；三名真人同侧时是 3v5 |
| `!ai e2 a1 lv2` | 加 2 个敌人、1 个队友，使用 2 级机体池 |
| `!ai e3 a2 lv4` | 加 3 个敌人、2 个队友，使用 4 级机体池 |
| `!ai e3 lv4 hard` | 3 个 4 级机体池的敌人，使用 Hard [战斗 AI](battle-ai.zh-CN.md)（可写 `easy`、`medium`、`hard`，默认 medium） |
| `!ai0` 或没有 `!ai` | 不加 AI |

`eN`、`aN` 是额外 AI 数量，不包括真人；`*` 表示填空位。敌友以每次开局时房主最终所在阵营为基准，
不固定红队或蓝队。指令不区分大小写，`lv1` 至 `lv5` 选择机体池。

### 常见组合

- 朋友一起打电脑：`!ai coop`。一人时是 1v7，三人时是 3v5，四人时是 4v4。
- 三人打四个电脑：`!ai coop e4 a0`；三人加一个 AI 队友打四个电脑：`!ai coop fill`。
- 真人之间也要对打：用原生分队，例如双方各有一名真人时，`!ai e4 a2` 得到房主侧 3 人、对面 5 人。
- 固定 3v3：建 6 人房再用 `!ai`。`!ai` 按房间容量补位，旧版的 `FillTeamSize` 设置已不使用。

### 真人分队与 AI 补位

真人分队和 AI 补位是两条独立的规则：

- **原生分队**（默认，或显式写 `versus`）：自由选边保留每个真人的选择；随机分队先随机真人，再以房主最终阵营计算敌友。对面的真人仍是敌人。
- **真人同队**（`coop`）：开局时所有真人跟随房主当前选择的阵营，AI 再按补位规则加入。它优先于房间的随机分队，其他真人的临时选边不会把朋友分开；房主可选任一边。

随机分队房若尚未给房主分配阵营，`coop` 使用第一阵营；要指定颜色，选择自由分队后由房主选边。

`coop` 单独使用默认只补对面；也可组合 `fill`、`enemy` 或精确 `eN aN`，例如 `!ai coop e4 a1`。
`versus` 单独使用默认双方补位。两种真人规则只能选一种，省略时保留原生分队。
`!rand` 仅随机各自机库中的出击机体，不控制队伍，也不决定 AI 补哪边。
房名显示整局规则；同队调整及 AI 加入在开局时完成，可在 TAB 战绩面板确认实际队伍。

8 人房中，不同补位意图的区别如下；人数按“房主侧 / 对面”排列：

| 已有真人 | `!ai fill` | `!ai enemy` |
|---|---|---|
| 1 / 0 | 加 3 / 4 个 AI，得到 4v4 | 加 0 / 7 个 AI，得到 1v7 |
| 3 / 0 | 加 1 / 4 个 AI，得到 4v4 | 加 0 / 5 个 AI，得到 3v5 |
| 2 / 1 | 加 2 / 3 个 AI，得到 4v4 | 加 0 / 5 个 AI，得到 2v6 |
| 4 / 0 | 加 0 / 4 个 AI，得到 4v4 | 加 0 / 4 个 AI，得到 4v4 |

每次开局都重新读取真人、当前房主和房间容量。换边、加入、离开或更换房主后，自动补位随之重算；
战斗中有人退出不会临时插入新的 AI。精确数量仍按原指令增加，不会自动改成平衡人数。
例如 `!ai coop e5 a0` 在三名真人时是 3v5，第四名真人加入后会因超额而取消开局；`!ai coop` 则自动变为 4v4。
双方补位尽量达到各半人数，但不拆散已经超过半数的真人队伍。AI 不占观战名额，也不会替换真人。

### 人数上限与取消开局

AI 房间总人数上限为 8，AI 可使用任意空闲槽位。以下情况会取消本次开局，而不是悄悄少加 AI：

- 请求的 AI 超出空位、缺少房主身份或机体池无法满足；
- 真人占满全房时使用 `coop`（没有敌方名额），应腾出名额或改用原生分队；
- 参数拼写错误、重复或互相冲突；`fill`、`enemy` 和数量规则只能选一种。

单侧人数超过地图出生点数时，轮流复用该侧现有出生点，可能出现重叠。

### 与长房名、随机机体组合

启用[长房名三端配套](room-titles.zh-CN.md)并更新 `pvp_ai` 后，可读取完整房名任意位置的指令，
上限为 128 个 Unicode 标量 / 512 字节 UTF-8。例如：
`朋友练习局，慢慢打欢迎新手 !ai e2 a1 lv4 !rand`。
另装并启用 `room_random` 后，真人每局随机，AI 仍使用自己的机体池；所有参战客户端仍需 `match_ai`。
`e2 a1 lv4` 放在 `!ai` 后、`!rand` 前。未启用长房名时，原生 20 字节上限仍然适用。
完整语法见[房名组合指令](room-commands.zh-CN.md)。

### 对局中

普通、死亡竞赛、Grid、队长和 Tag 模式均在原生倒计时解除玩家控制的同一帧启用 AI，三档难度相同；
倒计时期间 AI 不会提前移动或攻击。按住 TAB 可在原生战绩面板查看两队的 AI 名称、击杀、助攻和分数，
战绩沿用原生计分与排序，并随对局更新。

每局都会从机体池为每个 AI 重新抽取机体，不重复，并遵守该模式的点数和数量限制。
AI 在房主客户端运行，其他玩家显示同步副本。Grid/Tag 模式可使用 AI 卡组；
本机 AI 等待变形确认时，会通过原生玩家的确认流程继续当前动作，避免 NPC 消息逻辑重入变形状态。
模型已切换、同次动画尚未结束的完成确认也沿用本地接收流程，正常归还控制。
单向形态、新的技能变形、必杀延迟和复活处理仍保留各自的原生规则。
死亡后可通过原有观战功能查看 AI。复活、生命消耗和胜负按所选模式规则处理。
无论哪种难度，双方 AI 都会攻击敌方的真人和 AI，不会攻击队友。

AI 使用瞬间移动时，按原生流程移到出生点并保留当前血量；正常伤害和地图危险区域照常生效。
AI 会通过正常请求使用地图上的移动装置；可破坏的门按原生规则受伤、倒计时并由服务器移除。

启用[战斗 AI](battle-ai.zh-CN.md)后，地形路线可以主动接近有助于到达目标的推进装置。
装置的三维推进仍由原生控制；到达后，AI 从实际位置重新寻路并继续交战。
房主与参战客户端应同步更新，确保移动请求和通知使用配套组件。

AI 可以获得 MVP，但不能成为房主。结算时若第一名是 AI，仍在房间里的真人房主保留开局权限，
单人输给 AI 后也可以在同一房间继续开局；原生转交给其他真人的规则保留。

结算后，AI 通过原生离房流程从每个客户端的等待房列表退出，不会残留空名字或 LOADING 条目。
真人可在原房间重新准备、继续开局，配合 `!rand` 时也一样；每次开局按当前指令重新创建 AI。
所有承载这些房间的对战服务器都需更新，更新后重启相应服务端和客户端程序。

## 设置

在 SDGO Mod Manager 的“对战 AI · 服务端”中修改，保存后重启相应对战服务器；日志开关需点“显示开发信息”后显示。
数值保存在 `sdgo/mods/pvp_ai/mod.ini` 的 `[settings]`。

| 设置 | 默认值 | 含义 |
|---|---|---|
| `DefaultLevel` | 2 | 没有 `lvN` 时的机体池，范围 1–5 |
| `LifeCostGrade1`…`4` | 250/334/455/556 | C/B/A/S 级 AI 的死亡竞赛生命消耗；0 保留原值 |
| `Level1`…`Level5` | 见文件 | 各级机体池的 NPC 数据 id |
| `LogRoom` | 1 | 开发设置：记录开局房间信息 |
| `LogBattle` | 0 | 开发设置：记录计分、死亡和复活 |

自定义机体池时，两端需要对应的 NPC 和机体数据，见[增加更多机体](coop-wingmen.zh-CN.md#增加更多僚机机体)。
值后面不要写行内注释。客户端部分（“对战 AI · 客户端”）只有开发用的 `LogErrors`、`LogDiagnostics`，默认关闭。

日志在游戏或对战服务器目录的 `sdgo/logs/`。如果没有 AI，先检查两端 Mod 是否加载、
房名指令、可用机体池和队伍空位。
