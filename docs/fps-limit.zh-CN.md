# FPS 上限

在 **SDGO Mod Manager** 设置渲染帧率上限，游戏速度保持原样。
例如设置 160，允许最高 160 FPS 的渲染，逻辑更新仍为原生 60 Hz，移动和 AI 不会随帧率加速。

独立渲染限速与原生游戏速度需要 `fps_limit` 1.0.4 或更新版本。
使用较高上限前，请先更新旧版本。

[English](fps-limit.md)

| Mod | 安装位置 | 作用 |
|---|---|---|
| `fps_limit` | 客户端 | 独立设置渲染上限，游戏逻辑保持 60 Hz |

## 使用

1. 关闭游戏，打开 **SDGO Mod Manager**。
2. 选择客户端，启用「FPS 上限」，保存需要的数值。
3. 使用原启动器进入游戏。修改数值后需要重新启动游戏。

Manager 直接更新已有的 `config.xml`。安装 Mod 时保留原有数值及其他客户端设置，
无需安装服务端组件。

## 配置

| 设置 | 默认值 | 允许范围 | 生效方式 |
|---|---|---|---|
| FPS 上限 | 60 | 1–1000 的整数 | 重启客户端 |

数值保存在 `config.xml` 的 `Framework/Timer@updatefps`，Mod 不另存一份 FPS 配置。
缺失或无效的数值使用 60。

只有渲染上限跟随该设置。无论选择 30、60、120 还是 160，逻辑更新都保持原生 60 Hz。
分辨率、画面比例和原生时钟来源保持原样。

较慢的逻辑更新产生欠时时，画面仍继续绘制，避免繁忙的 AI 对战中逻辑还在运行、
画面却连续几秒不刷新。原生更新调度和累计时间继续保留，实际画面提交仍受所设上限限制。

上限表示允许的最高帧率。渲染负载、垂直同步和显示器刷新率仍可能限制实际显示效果，
提高上限并不保证性能随之提高。

## 兼容性与排错

支持的客户端为 `GOnline-54BE1568-00C97000`。客户端版本或所需指令不匹配时，Mod 不会启用。
安装与版本检查见[安装说明](setup.zh-CN.md)。

日志位于客户端目录的 `sdgo/logs/sdgo.log`。设置为 160 时，启动日志包含
`effective FPS cap=160`。

| 现象 | 检查方法 |
|---|---|
| 保存后没有变化 | 重启选定的客户端，检查 Mod 是否启用 |
| `invalid value; using 60` | 输入 1–1000 的整数 |
| 所需符号校验失败 | 使用支持的客户端和配套框架文件 |
| 渲染帧率低于上限 | 检查场景复杂度、AI 负载、垂直同步及显示设置 |
| AI 还在行动，画面却连续几秒不刷新 | 更新并启用 `fps_limit` 1.0.4 或更新版本，重启客户端 |

需要诊断性能时，可在「显示开发信息」中开启「帧率采样日志」，重启客户端。
日志中的 `render FPS sample` 记录每五秒成功 Present 提交的平均频率，遮挡和失败提交单独计数。
它测量的是渲染提交次数，不是显示器的物理刷新率。此诊断默认关闭，测试结束后可以关闭。

开发者可使用[原生 GameTest 的 FPS 场景](game-test.zh-CN.md#无需登录的-fps-参数验证)
复测参数读取和帧率限制。
